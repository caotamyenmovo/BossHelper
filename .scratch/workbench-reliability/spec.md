# 求职工作台整体优化

Status: resolved

用户已批准按整体评估顺序实施。仅修改 C 盘工作区；不向 F 盘同步或远程发布。

## 范围与约束

1. 面试会话生命周期：请求归属与取消、简历和岗位快照、当前题目及答案草稿恢复、保存失败保留输入、历史会话继续练习。
2. 本地保存：统一跨页面写入、版本冲突及删除检测、普通 JSON 序列化、旧数据迁移。
3. 简历一致性：明确未保存状态，AI 使用可见版本的快照，切换档案隔离分析和建议，导入不污染其他草稿。
4. 网页读取：诊断缺少授权、连接失败、页面加载、登录验证、标签关闭与超时，保留已取得来源并可重试。
5. 建议与体验：本地保存分析和有来源建议及输入快照，历史查看/删除，清楚显示当前简历、岗位、保存状态、AI 模型、练习状态。
6. 恢复可执行类型检查；生产构建并运行流程回归。

沿用现有 AI 配置；明确点击后才发送资料。公开网页读取及用户主动选帖保持 ADR 0001/0002 约束。导入保留已批准的整体替换语义。

## 已确认测试范围

沿用此前已确认的工作台流程 interface：开始/恢复/回答/继续/复盘，以及本地档案 CRUD、网页读取和真实扩展页面。重点验收切换期间旧 AI 响应隔离、刷新恢复、存储失败重试、并发保存与旧数据兼容。模拟仅放在 AI、浏览器和存储 adapter。

## 验收

- A 的延迟题目不能出现在 B；退出后迟到结果不能恢复已关闭会话。
- 当前题目和未提交答案可刷新恢复，提交失败输入不清空。
- 两页面保存不同档案均保留；旧版本更新/删除明确报冲突。
- 历史面试使用开始时简历，不因档案修改/删除而漂移。
- 可见草稿与 AI 输入一致，切换简历不显示另一份生成结果。
- 缺失小红书权限可立即说明原因，不用等到超时。
- 分析/建议可本地恢复、核对来源并删除。
- 核心流程回归、类型检查及 Chrome 构建通过。

## 验收结果（2026-11-09）

01–05 均已完成。类型检查和 Chrome 生产构建通过；116 项自动化测试全部通过；工作台、简历导入、公开内容读取及 AI 响应四组生产扩展浏览器流程通过。浏览器使用模拟网页及本地模型中转；未验证真实 Boss 登录态与本机小红书账号页面。构建保留现有样式、依赖输出格式和体积警告。使用步骤和完整改动说明集中在根目录 README.md。未同步 F 盘或 GitHub。
